Inside the pipeline

Six steps, each fixing something the raw logs get wrong

The data README is wrong in places, so every rule below comes from checking the files. Nothing is dropped silently: every removed or flagged row is counted in build_report.json.

01ingest.pyReads every file, checks the 8 columns and their types, decodes the event name from bytes to text.One file sits in two day folders: read once. ${files_read} of ${files_found} read, ${files_failed} failed.
02normalize.pyReads ts as Unix seconds and starts each match's clock at its first event. Decides bot or human.${doubled_count} journeys were logged twice in full: the copy goes. A file that logs BotPosition is a bot.
03journeys.pyGives each event a type (position, kill, death, storm death, loot) and cuts each journey at its first death.${after_death_dropped} positions were logged after the player died. Gaps over ${gap_limit} s break the path (${gaps} breaks).
04projection.pyTurns world x and z into a map position from 0 to 1. The only place this happens.The README's image size (1024 px) is wrong; positions don't depend on image size at all.
05heatmaps · zones · statsCounts kills and deaths per cell, spreads time along each step, finds hotspot regions, computes the statistics.Only human journeys count. A hotspot needs events from at least ${hot_matches} matches.
06export · imagesWrites the JSON files and the WebP minimaps, with no timestamps, so a rebuild gives identical bytes.Player IDs are replaced by a short hash. Match files are swapped in only after all ${match_files} are written.

The timestamp trap

The column is typed as milliseconds. Read that way, this row would be at ${ex_ms_iso} and the whole dataset would span a few minutes of 1970. As seconds, it falls on its folder's date.

Whose position is it?

An event's x and z are where the file's owner stood. So a kill marker sits where the killer stood, and a death marker where the victim fell.

Why only u and v leave

The browser never sees world units, so paths, markers and heatmaps all come from the same converted numbers. The ${uv_decimals}-decimal rounding is the only change.

Run time

What the browser downloads, and when

Nothing is computed from raw data in the browser. It downloads the index once, then the one file a view needs. Filtering, sorting and drawing happen on files already in memory.

Done in the browser

  • Filtering by map and date, sorting the match list.
  • Cutting each path at the playback time, every frame.
  • Painting the heatmap grid into a soft picture (display only; no values change).
  • Turning the cursor position back into world x, z for the readout.

Why there is no server

The data is fixed and every question the pages ask is known in advance, so the answers are files. No database to run, no API to keep alive, nothing that can fail on a reviewer's first visit.

Aggregation

How positions and events become a heatmap

Heatmaps are built from human journeys only. The ${grid}×${grid} grid holds the numbers; the soft picture on screen is painted from it and never changes them.

1 · Traffic: time along the route
${trace_svg}

Positions are about 5 s apart. Counting only the cell each sample lands in would leave the cells in between empty, so each step's time is spread along its straight line: here a ${trace_seconds} s step crosses ${trace_cells} cells, split by the distance inside each (computed with the pipeline's own trace_step).

Steps over ${gap_limit} s add nothing: where the player went is unknown.

2 · Kills and deaths: counts per cell

Each kill or death adds 1 to its cell. Thin lines: a corner of the ${grid}×${grid} grid. Thick lines: ${zones_grid}×${zones_grid} regions of 4×4 cells, which hotspots are judged on, because single cells mostly hold one event.

A region is a hotspot when

  • events come from at least ${hot_matches} different matches;
  • no single match gives over ${hot_share} % of its value;
  • it is among the ${hot_max} strongest that pass, per layer.
3 · In the browser: painted, not recomputed
  • Each non-zero cell is painted as a soft bump (Gaussian, σ = 1 cell) whose colour comes from that cell's own value; neighbours are never added up, so no peak is invented.
  • Traffic uses one teal to yellow palette on a log scale. Kills and deaths use four count classes: 1, 2–3, 4–9, 10+.
  • Hotspot outlines come straight from zones/<map>.json; hovering reads the grid, not the pixels.

Guarantees and limits

What the design makes sure of, and what it can't

The pipeline is the single source of every number on screen. These are the properties that follow from that, and the gaps the data itself leaves.

Reproducible

Same input, same bytes

No build timestamps and a fixed sort order, so make data on the same raw files gives byte-identical output. A change in a diff is a change in the data or the code.

Safe rebuilds

Nothing half-written

Match files are written to a staging folder, checked against the index (one file per match, right schema), and only then swapped in. The old folder goes last.

One source

Pages can't disagree

One clock, one bot rule, one coordinate function, and statistics computed once into stats.json. The pages read; they don't recalculate.

Private

No real IDs leave

Player IDs are hashed before export, raw logs are gitignored, and make check-ids scans everything trackable for real IDs.

Audited

Every exclusion counted

build_report.json lists files skipped, rows removed by reason, flags, journeys by type and the path breaks, so each cleaning step can be checked.

Fast first visit

Small, on demand

${web_total} in total, but a visit loads the index and one map first. A match file is ${match_median} at the median.

Limit

Recorded players only

Most matches have one recorded human. Everything describes what was logged, not every player in every match.

Limit

Straight lines between samples

Paths and traffic join samples about 5 s apart with straight lines. The real route between them is unknown.

Limit

No extraction event

A journey with no recorded death probably extracted, but the logs never say so; anything built on that is labelled inferred.
